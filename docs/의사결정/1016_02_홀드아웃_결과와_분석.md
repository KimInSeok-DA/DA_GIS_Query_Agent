## 배운 것

- **같은 출제자의 홀드아웃은 과대평가한다.** 개선용과 홀드아웃은 같은 사람이 같은 생각으로 만들어서, 개선이 홀드아웃에도 그대로 통했다(99%). 다른 출제자의 질문은 개선 때 생각하지 못한 오류(여러 값 열, SQL 논리)를 드러냈다
- **프롬프트로 막은 오류는 표현을 바꾸면 다시 나온다.** "몇 분 걸려?"(Q45)에는 통했던 규칙이 "걸어서 5분 거리"에는 통하지 않았다
- **실제 사용자 질문의 1/3은 기준이 애매했다**(30개 중 10개). 에이전트는 되묻지 않고 기준을 정해 밝히는 쪽을 택했다
- **근거 검사는 모델이 SQL에 넣은 숫자를 막지 못한다.** 근거 검사를 "도구 결과에 있는 숫자"로만 좁히면 A26을 잡을 수 있지만, 질문의 조건값(예: "300m 이내")을 쓰는 정상 답까지 걸린다. 질문에 나온 숫자와 도구 결과만 근거로 인정하는 방식이 다음 후보
- 채점 규칙은 실행 전에 다듬어도 빠뜨린 것이 있다(A27). 사람 검토가 필요하다
