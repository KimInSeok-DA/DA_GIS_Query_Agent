## 1. 도구 설명에 여러 값 열 안내 (적용)

A16 "운영기관별로 몇 개씩"에서 모델이 `GROUP BY operators`로 `서울교통공사;한국철도공사` 같은 조합마다 따로 셌다. 도구 설명에 `lines`는 `;` 구분이라고 적혀 있었지만 `operators`는 "운영기관"이라고만 적혀 있었다.

- `operators`도 `;` 구분 목록이라고 적고, 예를 들었다
- "lines·operators는 한 칸에 여러 값이 들어 있다. 노선별·운영기관별로 셀 때는 그대로 GROUP BY 하지 말고 나눠서 센다"와 나눠 세는 SQL 예시(`unnest(string_split(lines, ';'))`)를 넣었다
- 예시는 A16의 답을 그대로 주지 않도록 `operators`가 아니라 `lines`로 썼다
- 예시 SQL이 실제로 도는지 테스트를 넣었다(서울 안 역 기준 서울교통공사 225, 한국철도공사 59 — `answers.py`가 pandas로 따로 계산한 A16 정답과 같음)
- 데이터에서 본 것: 역 389개 중 `operators`에 여러 값이 든 역 53개, `lines` 91개. 9호선 운영기관이 `서울특별시 서울시메트로9호선㈜`(25)와 `서울시메트로9호선㈜`(13) 두 가지 표기로 나뉘어 있다(원 자료 그대로). 운영기관별로 세면 두 줄로 나온다

**효과는 아직 재지 않았다.** A16을 보고 고쳤으므로 holdout_ai로 다시 돌리면 고친 문항을 다시 푸는 것일 뿐이다. 새 외부 질문을 받아 재야 한다.

## 2. 근거 검사에서 모델이 쓴 SQL 숫자 빼기 (바꾸지 않음)

1016_02에서 A26의 가정 값 400m가 근거 검사를 통과한 이유는 모델이 SQL에 `near_dist_m <= 400`을 직접 넣어서다. 근거 검사는 도구 인자(모델이 쓴 SQL)의 숫자도 근거로 인정한다.

**바꾸기 전에 저장된 답으로 미리 돌렸다**(API 호출 없음). run4～holdout_ai1 기록의 최종 답·첫 답 363개에, SQL의 숫자 리터럴만 근거에서 빼는 규칙을 적용했다. `cover_500m`처럼 열 이름 안의 숫자는 남겼다(전부 빼면 "500m 반경"을 쓴 A07까지 걸렸다).

| 문항 | 새로 걸린 수치 | 판단 |
|---|---|---|
| A26 | 400 ("400m 이하(도보 5분 내외)") | 잡아야 할 것. 다만 이 답은 이미 거절 판정으로 오답 처리됐다 |
| A28 | 80 ("역세권 비율 80% 이상이면서 …") | 기준이 애매한 질문에서 모델이 기준을 스스로 정하고 밝힌 것. 잡으면 자기검증이 기준 설명을 지우게 만든다 |

- 나머지 361개는 결과가 같았다
- 두 경우는 구조가 같다(모델이 정한 값을 SQL에 넣고 답에 씀). 숫자만 보고는 "가정으로 바꾼 값"과 "기준을 밝힌 값"을 가를 수 없다

> 질문: "근거 검사에서 모델이 SQL에 직접 쓴 숫자를 근거에서 뺄까요? …" — 선택지 "바꾸지 않음 (추천)" / "바꿈"
> 사용자 선택: "바꾸지 않음 (추천)"

근거
- 363개 중 잡는 것 1개, 잘못 잡는 것 1개로 효과가 같고, 잡는 1개는 다른 검사(거절 판정)가 이미 잡는다
- 실제 질문의 1/3이 기준이 애매했다(1016_01). 그런 질문에서 기준을 밝히는 것은 바라는 행동이다
- 근거 검사는 평가 지표이기도 하다. 바꾸지 않으면 지금까지의 점수와 그대로 비교할 수 있다

대안과 바꾸는 조건
- 새 외부 질문에서 가정 환산 값이 거절 판정에도 걸리지 않고 통과하는 경우가 나오면 다시 본다
- README 한계("모델이 SQL에 직접 넣은 숫자는 근거로 인정되어 통과")는 그대로 둔다

## 3. 근거 검사의 km→m 비교 (고침, 결과 변화 없음)

미리 돌리는 중에 찾았다. 질문이 km(예: "1.5km")이고 답이 m("1,500m")이면 같은 값인데 근거 없음으로 걸렸다(비교식이 m→km 방향만 봄). 지금까지는 모델이 SQL에 1500을 넣어서 가려져 있었다.

- 비교식에 반대 방향(답 = 근거 × 1000)을 넣고 테스트를 추가했다
- 저장된 기록 전부(run1～holdout_ai1)를 다시 계산해 **결과가 바뀐 답 0개**를 확인했다. 지금까지 낸 근거 없는 수치는 그대로다
