## 고친 것

| 문제 (1016_04) | 고친 것 |
|---|---|
| B23: 도구 호출 상한 뒤 빈 답 | 최종 답이 비면 정해 둔 문장 "데이터로 답을 확인하지 못했습니다. 동·구 이름이나 기준을 더 구체적으로 해서 다시 물어 주세요."로 답한다. 숫자가 없는 고정 문장이라 근거 검사와 부딪히지 않는다 |
| B27·B49: 숫자 없이 틀린 결론 단정 | 프롬프트 규칙 2에 "'있다/없다', '모두 그렇다' 같은 결론도 도구 결과로 확인한 것만 말한다. 조회가 실패했거나 확인하지 못했으면 단정하지 말고 확인하지 못했다고 말한다"를 넣었다. 도구 설명에 "stations에는 역이 속한 구·동 정보가 없다. emd.n_station은 동 안의 역 '수'만 있고 어느 역인지는 없다"를 넣었다 |
| 노선 표기 차이(`8호선`·`수도권 광역철도 8호선` 등) | 도구 설명에 표기가 다른 예 세 쌍과 "노선을 찾을 때는 `LIKE '%9호선%'`처럼 포함 여부로 찾는다"를 넣었다 |
| B28: 음수 부호 | 답의 숫자는 부호 없이 읽는데 근거(도구 결과)는 부호가 남아 맞지 않았다. 근거 숫자도 절댓값으로 비교한다 |
| B32·B50·A20: "500" 오탐 | 답에서 열 이름(`cover_500m`처럼 `_`가 든 영문 이름)과 데이터 정의 "500m 반경"·"반경 500m"을 숫자로 보지 않는다. "역까지 500m" 같은 거리 값은 그대로 검사한다 |

## 근거 검사 수정은 저장된 답으로 미리 돌렸다 (API 호출 없음)

run4～holdout_ai2 기록의 최종 답·첫 답 417개

- 결과가 바뀐 답 5개, 모두 오탐이 사라진 것: holdout_ai2 B28(음수, 최종·첫 답), B32 첫 답, B50 최종·첫 답, holdout_ai1 A20 첫 답
- **새로 걸린 숫자 0개**
- 처음에는 도구 결과 쪽 문자열에서도 열 이름 안 숫자를 뺐는데, 미리 돌려 보니 15개 답에 새 오탐이 생겼다("역 500m 커버 비율"처럼 "반경"이 없는 표현 등). 그래서 답 쪽에서만 뺀다
- 이 수정으로 holdout_ai2 보고서의 최종 근거 없는 수치 2/50은 0/50이 된다. **이미 낸 보고서 수치는 고치지 않는다**(1016_04에 사람 검토로 "둘 다 오탐"이라고 적어 둠)

## 하지 않은 것

- 자기검증이 모델이 정한 기준값(B19의 200·400m, A28의 400m)을 잡는 오탐은 그대로다. 숫자만으로는 "기준으로 정한 값"과 "지어낸 값"을 가를 수 없다(1016_03과 같은 이유)
- 숫자 없는 틀린 결론은 프롬프트로만 막았다. 코드로 잡는 검사는 없다

## 효과를 재려면

프롬프트·도구 설명이 바뀌었으므로, 지금까지의 질문(holdout_ai2 포함)은 더 이상 처음 보는 질문이 아니다. 새 외부 질문을 받아 재야 한다. 특히 B27·B49 같은 "확인할 수 없는 것을 묻는" 질문에서 단정이 줄었는지 사람이 읽어 확인한다.
