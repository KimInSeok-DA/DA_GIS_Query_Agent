## 1. 근거 검사: 할루시네이션을 코드로 잰다

**전**: 할루시네이션 여부를 사람(AI)이 답을 읽고 판단했다.
**후**: 답에 나온 숫자마다 도구 인자·결과, 질문, 앞 대화에 같은 값이 있는지 자동으로 본다. 없으면 "근거 없는 수치"로 기록하고, 보고서에 정답률과 따로 "근거 없는 수치가 나온 답 n/N"을 적는다.

| 규칙 | 이유 |
|---|---|
| 답에 쓴 자릿수로 반올림해 같으면 근거 있음 | 630.357143을 630.36·630으로 쓰는 것은 지어낸 것이 아님 |
| m↔km 환산은 같은 값 | 0.63km = 630m |
| 문자열 안 숫자도 근거(명동2가, `cover_500m`의 500) | 동 이름·열 이름에서 온 숫자 |
| 목록 번호("1. ")·순위("2위")는 뺌 | 사실 주장이 아님 |
| 실행 중에 전체 도구 결과로 계산 | 실행 기록에는 도구 결과를 앞 5행만 남기므로, 기록으로 계산하면 근거 없음이 실제보다 많이 나온다 |

이름(역·동)은 검사하지 않는다. 숫자보다 표현이 다양하고(학동/학동역), 지금까지 지어낸 이름은 없었다.

run1b의 Q29는 `SELECT 290 - 256`으로 계산해서 근거가 있었다. 힌트를 뺀 뒤 두 번 모두 직접 계산으로 바뀌었다.

## 2. 계산도 SQL로 (억제)

시스템 프롬프트 1번에 한 줄 추가:

> 차이·합계·평균·비율 같은 계산도 머릿속으로 하지 말고 run_sql로 계산한 결과를 말한다.

Q29의 34는 맞았지만, 평균이나 큰 수의 계산은 모델이 틀릴 수 있다. 프로젝트 규칙("도구 결과에 없는 수치를 말하지 않는다")과도 어긋난다. 효과는 근거 검사 지표로 잰다: 개선용 실행에서 **근거 없는 수치 1건 → 0건**이 되는지(2026-10-16).

이것이 이 프로젝트에서 처음으로 "오답(규칙 위반) 분석 → 개선 → 2차 측정" 순서를 갖춘 개선이다.
