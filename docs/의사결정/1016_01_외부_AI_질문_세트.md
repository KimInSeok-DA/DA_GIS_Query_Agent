# 1016_01 외부 질문 세트: 다른 AI가 쓴 질문 30개 (holdout_ai)

- 상태: 질문·정답 확정, **실행 전에 커밋**(2026-10-16)
- 코드: `eval/questions.csv`(A01～A30), `src/answers.py`(`compute_holdout_ai`), `src/grade.py`·`src/eval.py`(기준 애매 문항은 정답률에서 뺌)
- 받은 방법: [`eval/holdout_ai_지시문.md`](../../eval/holdout_ai_지시문.md)

## 왜

기존 120문항은 도구와 프롬프트를 만든 쪽(Claude)이 썼다. 도구 설명의 말투와 예상한 오류에 문항이 맞춰져 있을 수 있다. 데이터 구조를 모르는 출제자의 질문이 필요했다.

## 사용자와 나눈 판단

> 사용자: "이거 다른 AI 에이전트(antigravity)한테 질문을 만들어내라고 해도 될거 같은데 어떻게 생각해?"

- 판단: 좋다. 다만 사람이 쓴 질문을 완전히 대신하지는 못하고(AI 말투), 따로 세는 세트로 쓴다
- 막아야 할 것: 출제자가 열 이름·도구 설명·기존 문항을 보는 것. 저장소가 공개라 웹 검색도 막는다

> 사용자: "어떤 것만 읽으라고도 해야할 거 같은데?" / "클로드 코드 쓰면 되는 거야?" / "나 gpt 유료버전 없어" / "웹이라고 하면 파일같은 것도 올려서 읽혀야하잖아"

| 안 | 판단 |
|---|---|
| Antigravity·Claude Code + 빈 폴더 | 파일·폴더 접근이 가능해서 막기가 어렵다. Claude Code는 기존 문항 출제자와 같은 계열 |
| Gemini 웹 | 답하는 모델과 같은 계열이라 질문이 쉬워질 수 있다 |
| **ChatGPT 무료 웹(선택)** | 파일을 볼 수 없고, 출제자(Claude)·답하는 모델(Gemini)과 계열이 다르다. 질문 30개는 무료로 충분 |

- 파일은 올리지 않는다. CSV를 올리면 열 이름과 실제 값을 보게 되어 목적이 깨진다. 데이터는 평범한 말로만 설명했다

## 받은 질문

- 1차 30개: 말투가 깔끔했다(예상한 한계). 1～3번이 지시문의 예시 동 이름(역삼동·청담동·명동2가)을 그대로 썼다 — 지시문 탓
- 사용자가 같은 대화에서 말투 지적만 보내 2차 30개를 받았다. **2차를 그대로 쓴다.** 함정 정보는 전하지 않았다

## 정답 규칙

| 구분 | 문항 | 처리 |
|---|---|---|
| 자동 채점 | 20개 | 정답·거절·`absent`를 코드로 계산(pandas, 에이전트와 다른 경로) |
| 기준 애매 | 10개(A04·05·06·07·11·14·17·25·28·30) | "추천", "편한", "좋은", "높은데 먼"처럼 기준이 질문에 없어 정답이 하나로 정해지지 않는다. **정답률에서 빼고**, 근거 없는 수치와 답(기준을 밝히거나 되묻는지)을 직접 읽는다 |

자동 채점 문항 중 판단이 들어간 것

- A01 "역삼동 젤 가까운 역": '역삼'은 '역삼동' 안에 있어 글자 검사가 헛통과한다 → '역삼동'이 아닌 '역삼'이 나와야 한다
- A02 "성수동 역 몇개": **성수동이라는 법정동은 없다**(성수동1가·2가). 둘 다 말해야 맞다. 하나로 바꿔치기하면 오답(1015_11 청담1가와 같은 유형)
- A09 "지하철 없는 동도 있나??": 동 경계 안에 역이 없는 동 281개. 예/아니오 질문이라 **개수(281)를 말하거나 그런 동을 하나라도 들면** 맞다
- A12 "신림동 가까운 역이 신림역 맞지?": 틀린 전제. 실제는 서울대벤처타운역(998m)
- A13 "역세권 비율 제일 높은 동": 100%인 동이 113개로 동점. 하나만 고르면 오답. **동점 개수를 말하거나 '여러 곳·동점·공동'을 알리면** 맞다
- A15 "역삼동에서 그 다음으로 가까운 역": 좌표로 계산. 선릉(999.8m)과 언주(1,007.9m)가 8m 차이로 가깝다
- A16 "서울 지하철역 운영기관별 개수": 역 표에는 서울 밖 역도 있다. 사용자는 이를 모르므로 **서울 안 역 기준(서울교통공사 225, 한국철도공사 59)과 표 전체 기준(240, 104)을 모두 인정**한다. 기준을 섞으면 오답
- A23: 개선용 Q44와 같은 내용(서로 가장 가까운 두 역). 문장은 다르다
- A21 "500미터 안에 동 전체가 다 들어가는 곳 있어?": A09와 같은 기준(113개를 말하거나 100%인 동을 하나라도 들면 맞다)
- A24 "종로쪽 역 여러개 있는 데": 동 안 역 2개 이상은 창신동 하나
- A26 "걸어서 5분 거리": 질문에 '5분'이 있어 '분'이 나오는 것은 막지 않고, 걷는 속도를 가정해 환산했는지(분당 80m 등) 본다
- A27 "강남구는 모든 동에 역 있는 거 아님?": 틀린 전제. 역이 없는 동 4개

## 채점 규칙 다듬기 (실행 전)

처음 규칙 중 5개(A01·A09·A13·A16·A21)는 맞는 답도 오답으로 만들 수 있었다. 예: "네, 있어요. 평창동 등"은 맞는 답인데 281을 말하지 않아 오답이 된다.

> 사용자: "규칙 어떻게 하는 게 나을 거 같아?" / "지금 이 프로젝트에서의 목적와 취지를 고려해볼 때 어떻게 하는 게 좋겠어?"

- 판단: 이 프로젝트가 보여 줄 것은 높은 점수가 아니라 믿을 수 있게 재는 방법이다
  1. **틀렸다고 알고 있는 규칙은 고친다.** 맞는 답을 오답으로 만드는 규칙은 엄격함이 아니라 잡음이다. 함정이 노린 부분(바꿔치기·동점 무시·가정 환산·전제 동조)은 그대로 엄격하게 둔다
  2. **규칙을 언제 정했는지 증명할 수 있게 한다.** 규칙을 느슨하게 하면 점수가 오르므로 "결과를 보고 맞춘 것 아니냐"는 의심을 받는다 → 정답 규칙을 **실행 전에 커밋·푸시**해 커밋 시각을 증거로 남긴다. 실행 후 채점 오류를 찾으면 점수를 고치지 않고 따로 적는다
  3. **실행 후 사람이 답을 읽는다.** 오답 전부, 기준 애매 10개, 정답 일부를 읽어 채점기와 판단이 갈린 경우를 센다(채점기 신뢰도)
- 사용자 결정: "그래. 추천해준대로 진행하자"
- 구현: 검사 종류 2개 추가 — `present`(띄어쓰기를 지운 답에 이 표현이 있어야 함), `one_of`(여러 답 방식 중 하나를 모두 통과하면 됨). 예로 드는 동 이름은 다른 동·역 이름과 헷갈리는 것과 두 글자 이름(다동·궁동: "있습니다 동작구" → "다동")을 뺐다. 맞는 답·틀린 답 예시 테스트 15개

## 한계

- AI가 쓴 질문이다. 2차도 사람이 직접 쓴 질문보다는 정돈되어 있을 수 있다
- 1차를 본 뒤 말투만 바꿔 다시 받았다. 2차를 고른 것은 사용자 판단이다
- 기준 애매 10개는 자동 정답률에 들어가지 않는다. 실제 사용자 질문에는 이런 질문이 많다는 사실 자체가 발견이다(30개 중 10개)

## 바꾸는 조건

- 정답 규칙은 실행 전 확정(커밋). 실행 후 채점이 틀렸음을 발견하면 규칙을 고치지 않고, 원래 점수와 함께 "채점 오류"로 따로 적는다
