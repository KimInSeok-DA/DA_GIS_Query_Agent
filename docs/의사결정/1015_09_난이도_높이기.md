# 1015_09 평가 난이도 높이기: 힌트 제거, 공간 계산 추가

- 상태: 확정 (사용자 결정, 2026-10-15). 거절 판정 변경과 할루시네이션 대응은 [1015_10](1015_10_할루시네이션_측정과_억제.md)
- 이전 결정: [1015_08 채점 수정과 어려운 문항](1015_08_채점_수정과_어려운_문항.md)
- 코드: `src/agent.py`(시스템 프롬프트), `src/tools.py`(도구 설명, `dist_m` 매크로), `src/answers.py`, `eval/questions.csv`

## 배경: 만점이 문제인 이유

run1b(개선용 40문항)는 40/40이었다. 에이전트가 완벽하다는 뜻이 아니라 **평가 세트가 변별력을 잃었다**는 뜻이다. 만점인 시험으로는 개선 전후나 모델 간 차이를 잴 수 없다.

원인으로 본 것(영향이 큰 순서)

1. **출제자와 답 준비자가 같다.** 질문·시스템 프롬프트·도구 설명을 모두 같은 사람(AI)이 썼다. 시스템 프롬프트에 "버스·인구·도보 시간 등은 데이터에 없다고 답하라"고 적었는데 Q25·Q27·Q28의 주제 그대로였다. 도구 설명에는 "신사동: 은평구·강남구, 신정동: 마포구·양천구"로 함정의 답을 적어 두었다
2. **질문 표현이 열 설명과 같다.** "역 500m 반경이 동 면적의 몇 %를 덮어"는 `cover_500m` 설명을 옮긴 말이다
3. **도구로 할 수 있는 일이 좁다.** 미리 계산된 값(가장 가까운 역·거리 등)을 꺼내는 표 조회뿐이라 SQL 한두 번으로 끝난다
4. 한 번만 실행해 답의 흔들림을 재지 않았다
5. 채점이 숫자 하나만 맞아도 통과시키는 너그러운 구조다

데이터 크기(467행)는 주원인이 아니다. 에이전트는 행을 읽지 않고 표 구조만 보고 SQL을 짜기 때문에, 행이 많아도 열 구조가 같으면 난이도는 거의 같다.

## 검토한 안

| 안 | 내용 | 판단 |
|---|---|---|
| A 데이터 추가(인구·부동산 등) | 표 결합이 진짜 어려워짐 | 데이터 확보·라이선스·정답 재설계에 시간이 들어 목표일(10-16)과 맞지 않음 |
| **B 같은 데이터로 난이도 높이기(선택)** | 힌트 제거, 공간 계산 도구, 사용자 작성 질문, 반복 실행 | 새 데이터·라이선스 없이, 원인 1～3을 직접 겨냥 |

## 한 것

### 1. 힌트 제거 (원인 1)

| 위치 | 전 | 후 |
|---|---|---|
| 시스템 프롬프트 2번 | 도구로 확인할 수 없는 정보(버스·인구·가격·도보 시간·서울 밖 지역 등)는 … | 도구로 확인할 수 없는 정보는 … |
| `run_sql` 설명 | 같은 동 이름이 여러 구에 있다(신사동: 은평구·강남구, 신정동: 마포구·양천구) | 같은 동 이름이 여러 구에 있을 수 있다 |
| `find_dong` 예시 | 신사동, 강남구 신사동 | 청운동, 종로구 청운동(평가 질문에 없는 동) |

되묻기 규칙(시스템 프롬프트 3번)은 사용자가 정한 제품 동작이라 남겼다. 어떤 동인지는 알려 주지 않는다.

같은 40문항을 힌트만 뺀 상태로 다시 돌려 힌트의 영향만 따로 쟀다(run2_nohint, 아래 결과).

### 2. 공간 계산 추가 (원인 3)

데이터에 이미 동 대표점 좌표(`rep_lon`, `rep_lat`)와 역 좌표(`lon`, `lat`)가 있다. 이걸로 **두 지점 사이 거리를 새로 재는 SQL 함수 `dist_m`**을 넣었다.

| 안 | 판단 |
|---|---|
| **SQL 매크로 `dist_m(lon1, lat1, lon2, lat2)` (선택)** | 에이전트가 SQL 안에서 조건·정렬·조인과 자유롭게 조합한다. 순수 SQL이라 5초 상한이 그대로 걸린다(3중 조인에서 중단 확인) |
| 별도 도구(`stations_within(역, 반경)` 등) | 질문 모양마다 도구가 늘어나고, 조합은 에이전트가 못 한다 |
| Python 함수를 SQL에 등록(UDF) | 시간 상한이 Python 실행 중에는 잘 안 걸릴 수 있다 |
| DuckDB spatial 확장 | 설치에 외부 접근이 필요한데, 안전장치로 외부 접근을 막아 두었다 |

공식은 하버사인(지구 반지름 6,371,008.8m). 맞는지는 원본으로 확인했다: 동 대표점에서 모든 역까지 거리를 재면 **467개 동 모두 원본의 가장 가까운 역과 같은 역**이 나오고, 거리 차이는 최대 6m(원본은 평면 좌표로 쟀을 것으로 보임). `tests/test_answers.py`에 넣었다.

정답은 `src/answers.py`가 numpy로 따로 계산한다(에이전트는 SQL 매크로).

### 공간 계산 문항 (개선용 4, 홀드아웃 4+2)

| ID | 질문 | 정답 | 무엇을 보나 |
|---|---|---|---|
| Q41 | 강남역과 역삼역 사이 직선거리 | 819m(±10) | 역 두 개 좌표 → 거리 |
| Q42 | 홍대입구역에서 1km 안에 대표점이 있는 법정동 | 5개 동 이름 | 반경 검색 |
| Q43 | 논현동에서 가장 가까운 9호선 역 | 언주 | 노선 필터(표기 2가지) + 거리 정렬. `near_station`(학동)으로는 답할 수 없음 |
| Q44 | 서울 안 역 중 서로 가장 가까운 두 역과 거리 | 신용산, 288m | 자기 조인 |
| H61～H66 | 잠실–삼성 거리(km로 물음), 여의도역 2km 안 다른 역 수, 평창동에서 가장 가까운 3호선 역, 서울역에서 가장 가까운 다른 역, 강남역에서 가장 먼 강남구 동, 서울역에서 가장 가까운 동 | | 단위 변환, 자기 자신 빼기, **역 이름이 '서울'(서울역 아님)** |

설계에서 막은 것
- **경계 근처 값**: 반경 질문은 경계에서 50m 안에 값이 있으면 정답 계산이 멈춘다. "강남역 1km 안의 동"은 해당 동이 0개이고 가장 가까운 동이 경계와 12m 차이라 뺐다
- **동점 근처**: 가장 가까운/먼 것을 묻는 문항은 1·2위 차이를 확인했다(최소 41m)
- **글자 포함 함정**: Q44의 '용산'은 '신용산' 안에 들어 있어 글자 검사로는 빠져도 통과한다 → 거리 숫자로 확인
- **대표점 기준**: 동까지의 거리는 경계가 아니라 대표점 기준이다. 질문에 "대표점"을 밝혔다

질문 수: 개선용 44, 홀드아웃 66(holdout 44 + holdout_extra 22), 모두 110개.

## 결과

| 실행 | 조건 | 정답 | 요청 | 유료 환산 |
|---|---|---|---|---|
| run1b | 힌트 있음, 40문항 | 40/40 | 87 | $0.031 |
| run2_nohint | 힌트 제거, 같은 40문항 | **40/40** | 84 | $0.029 |
| run3_spatial | 힌트 제거 + `dist_m`, 44문항 | **42/44** | 94 | $0.036 |

모두 gemini-3.5-flash-lite 무료 등급(실제 비용 0).

- **힌트는 점수를 만들지 않았다.** 힌트를 빼도 신사동·신정동은 되물었고, 버스·인구·도보 시간은 없다고 답했다. 원인 1은 거의 배제
- **공간 계산 4문항 모두 정답.** `dist_m`을 조건·정렬·자기 조인(`s1.station_id < s2.station_id`)과 조합했다. Q43은 처음에 `near_station`으로 조인했다가 빈 결과가 나오자 스스로 `dist_m` 정렬로 바꿔 풀었다
- **오답 2개(Q25·Q28)는 다시 거절 판정 문제.** 답 내용은 맞다
  - Q25: "버스 정류장 개수 데이터는 없습니다. 다만 … 면적은 3.495㎢ …"
  - Q28: "… 직선거리는 44m입니다. 다만, 제공된 데이터에는 직선거리만 포함되어 있으며 … 보행 시간 정보는 없습니다."
  - "데이터에"로 시작하지 않거나, "없"까지 12자가 넘는다. 힌트를 뺀 뒤 거절 문장이 다양해졌고, 같은 프롬프트에서도 실행마다 표현이 달라진다(Q25는 run2_nohint에서는 "데이터에 없습니다"로 통과)
  - 채점 규칙은 문장 단위로 바꿨다(아래, 1015_10). 다시 채점하면 run3_spatial 44/44

### 거절 판정을 문장 단위로 바꿀지 → 바꿈(1015_10)

후보: **한 문장 안에 (데이터|정보|자료)와 (없|포함되어 있지 않|들어 있지 않|제공되지 않)이 함께 있으면 거절.** 지금까지 실행 4번의 답에 적용하면 거절 문항은 모두 거절로 판정되고(run3 2/4 → 4/4), 거절이 아닌 문항 중 거절로 잘못 걸리는 답은 0개다. 남는 약점: "데이터에 따르면 정류장은 12개이고 역은 없습니다"처럼 수치를 지어내면서 "데이터·없"이 한 문장에 함께 나오면 통과한다.

## 사용자와 나눈 판단

- "완벽한 것도 오히려 문제 아닌가? 왜 안틀렸을까" → 만점 원인 분석(위 배경)
