# 1015_12 자기검증 단계: 근거 없는 수치를 코드로 걸러 다시 답하게 하기

- 상태: 적용, 개선용 48문항으로 확인 (사용자 "다음 작업 진행하자", 2026-10-15)
- 이전 결정: [1015_11 run4 오류 분석과 개선](1015_11_run4_오류_분석과_개선.md)(정답률과 근거 없는 수치를 따로 센다, A)
- 코드: `src/agent.py`(`run`의 `self_check`), `src/eval.py`(`--no-check`, 첫 답 기록), `src/app.py`(자기검증 토글), `tests/test_agent.py`

## 왜

run5b Q48에서 모델이 도구를 부르지 않고 "고속터미널역 669m"(실제 208m)를 지어냈다. 시스템 프롬프트 1번이 이미 "도구 결과에 있는 것만 말한다"고 하는데도 나왔다. 규칙 문장을 더 쓰는 것으로는 한계가 있어서, **프롬프트에 부탁하지 않고 코드로 막는 단계**를 넣는다.

## 사용자와 나눈 판단

> 사용자: "자기검증 단계 필요하겠네. 다만 이 프로젝트의 결과물이 어떤 걸 보여주느냐에 따라서 조정이 필요하긴 하지. 너의 판단은 어때?"

판단: 넣는다. 다만 "할루시네이션을 0으로 만들었다"가 아니라 "모델은 가끔 지어낸다. 그걸 재고, 코드로 막고, 막기 전 수치도 숨기지 않는다"를 보여 주는 방식으로 넣는다.

- 위험: 평가에 쓰는 근거 검사로 답을 고치게 하면, 최종 답의 근거 없는 수치는 **구조상 0에 가까워진다.** 그 0은 모델이 정직해서가 아니라 검사기가 걸러서 나온 숫자다
- 그래서 세 가지를 함께 기록한다

| 지표 | 보여 주는 것 |
|---|---|
| 검증 전 첫 답의 근거 없는 수치(와 정답) | 모델 자체가 얼마나 지어내는가. 검증 단계와 무관 |
| 검증 후 최종 답의 근거 없는 수치(와 정답) | 시스템이 사용자에게 내보내는 품질 |
| 자기검증 개입 횟수 | 가드레일이 실제로 몇 번 일했나 |

- 정답 판정(정답 숫자·거절·`absent`)은 자기검증이 쓰지 않는 독립된 검사로 그대로 둔다
- 끄고 켤 수 있게 한다(`--no-check`, 화면 토글)

> 사용자: "다음 작업 진행하자 / 브랜치 새로 파서 작업해"

## 동작

1. 모델이 최종 답을 내면 코드가 `ungrounded_numbers`(1015_10)로 답의 숫자를 도구 인자·결과, 질문, 앞 대화와 대조한다
2. 근거 없는 숫자가 있으면 그 답을 대화에 넣고 "[자동 검증] 답의 수치 669은(는) 도구 결과에 없습니다. 도구로 확인해서 고치거나, 확인할 수 없으면 그 수치를 빼고 다시 답하세요."를 보낸다. 이때 모델은 도구를 다시 부를 수 있다
3. **1번만** 다시 묻는다. 다시 답해도 근거가 없으면 그대로 내보내고, 평가의 근거 검사와 화면 경고가 잡는다(무한 반복 방지)
4. 근거가 있는 답은 추가 호출이 없다

|---|---|---|---|
| run4·run4b_fix·run4c_fix·run5a～c (전체 도구 결과로 계산) | 207 | 2 | run4b_fix Q45 "분당 80m로 약 13분", run5b Q48 "669m" — 둘 다 실제로 지어낸 것 |

- 목록 번호 등을 잘못 잡아 **맞는 답을 고치게 했을 경우는 0건**. 맞는 답을 망가뜨릴 걱정은 작다는 근거로 삼았다
- Q29처럼 값이 맞는 직접 계산도 개입 대상이다. 규칙상 SQL로 계산해야 하므로 의도한 동작이고, 호출 1번이 더 든다

## 결과

개선용 48문항, 자기검증 켬(run6_check, `outputs/eval_report_run6_check.md`)

| 기준 | 정답 | 근거 없는 수치가 나온 답 |
|---|---|---|
| 검증 전 첫 답 | 48/48 | 2/48 |
| **검증 후 최종 답** | **48/48** | **0/48** |

- 자기검증 개입 2회, 모델 호출 107회(run5a～c 103회), 입력 110,555 · 출력 4,872 토큰, 유료 환산 $0.045(실제 0)
- 개입한 두 답을 직접 읽었다. **둘 다 데이터 값을 지어낸 것은 아니었다**

| 문항 | 첫 답 | 고친 답 | 판단 |
|---|---|---|---|
| Q11 | "…반포동이며, 역 수는 6개입니다. (환승역은 1개로 계산)" | 괄호를 뺀 같은 답 | **오탐.** "환승역은 1개"는 도구 설명(`n_station`)에 있는 말인데, 근거 검사는 도구 설명을 근거로 보지 않는다. 고친 답도 맞지만 계산 기준 설명 하나가 빠졌다 |
| Q32 | "…긴 구는 10개 구야? 가 아니라 **17개 구**야." | "…긴 구는 **17개**야." | 질문·도구 결과 어디에도 없는 10이 섞인 이상한 문장. 맞게 걸렀다 |

- 오탐 1건의 손해: 모델 호출 1번, 계산 기준 설명 하나. 정답은 그대로였다
- 도구 설명을 근거에 넣으면 이 오탐은 없어지지만, 설명에 있는 500·200 같은 숫자가 근거로 인정돼 "500m" 같은 지어낸 값을 놓칠 수 있다. **근거 검사는 바꾸지 않고** 오탐으로 기록한다(근거 검사는 평가 지표이기도 함)
- 이번 실행에서는 run5b Q48 같은 지어낸 거리가 나오지 않았다. 한 번 실행으로는 효과를 말할 수 없다는 한계(아래) 그대로다

## 한계

- **효과를 숫자로 증명하기 어렵다.** 144번 중 1번 나온 일이라, 몇 번 더 돌려서 "줄었다"고 말할 수 있는 빈도가 아니다. 동작은 가짜 클라이언트 테스트로 확인하고("지어낸 답 → 다시 묻기 → 고친 답", "1번만", "다시 물을 때 도구 호출 가능", "끄면 추가 호출 없음"), 실제 실행에서는 개입 사례를 기록해 직접 읽는다
- 숫자만 검사한다. 지어낸 역 이름·동 이름은 못 잡는다
- 검사 기준이 평가와 같다. 그래서 최종 답의 근거 없는 수치만으로 개선을 말하지 않고, 첫 답 기준을 함께 적는다

## 바꾸는 조건

- 개입이 맞는 답을 고치게 하는 사례(오탐)가 나오면 검사 규칙을 보거나 개입을 끈다. 단, 근거 검사 규칙은 평가 지표이기도 해서 홀드아웃 전에만 바꾼다
